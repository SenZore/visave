# Firefox release notes

This guide describes Firefox distribution and the checks Visave needs before a public release. It is not legal advice. Mozilla's current policies apply whether Visave is listed on AMO or self-distributed, and platforms can change their terms.

## Recommendation

Prepare a signed, unlisted AMO package first. It gives ordinary Firefox users a persistent install while keeping the add-on off AMO's public catalog. An AMO public listing can follow after the package, privacy disclosures, native installer, and review details are ready. GitHub can host the source and release assets, but an unsigned extension ZIP is only useful for temporary developer testing in normal Firefox.

Firefox Release and Beta require Mozilla-signed extensions. Mozilla signs both listed and unlisted submissions. A self-hosted XPI still needs signing; users can then install it from file. `about:debugging` temporary loading is for development and the add-on must be loaded again after Firefox restarts. Nightly, Developer Edition, and ESR have developer/testing signing overrides, but asking ordinary users to weaken signature enforcement is a poor public install path. See [Mozilla's signing and distribution overview](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/), [self-distribution guide](https://extensionworkshop.com/documentation/publish/self-distribution/), and [Firefox's signing explanation](https://support.mozilla.org/en-US/kb/add-on-signing-in-firefox).

## Before submitting to AMO

1. **Validate the manifest data declaration.** Version 0.3.1 declares `browsingActivity`, `websiteContent`, and `websiteActivity`, and sets `incognito` to `not_allowed`. Those data categories correspond to URLs, inspected media/request details, and the user-started download action passed to the companion. `websiteActivity` is needed because the extension sends the selected URL and download settings to its native companion when the user starts a download; this is product functionality, not analytics or background activity tracking. When the optional cookie choice is selected, yt-dlp uses the Firefox cookie database with the most recent modification time among profiles it finds, excluding Firefox containers; this may differ from the profile the user is currently viewing. Mozilla requires native-messaging data to be declared; verify Firefox's install and upgrade disclosures with the exact AMO package and make sure the listing and privacy notice agree. Mozilla's data taxonomy identifies saving and downloading as website activity. The cookie checkbox remains an additional per-download choice, not a substitute for Firefox's required install disclosure. The built-in disclosure is supported in Firefox 140+ desktop and 142+ Android; this manifest currently sets those minimum versions. The declaration is present in 0.3.1, but Firefox's actual install acceptance and AMO reviewer validation remain to be checked. See the [pinned yt-dlp cookie-loader source](https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/yt_dlp/cookies.py#L141) and [cookie option documentation](https://github.com/yt-dlp/yt-dlp#filesystem-options).
2. **Keep permission scope and purpose clear.** While enabled, Visave requests `http://*/*` and `https://*/*` host access and injects its content script across eligible HTTP(S) pages, including when the popup is closed, to inspect video elements. `webRequest` records media-like response URLs and headers. Explain why broad access is needed, accurately describe the product as an on-page video inspector/downloader, and assess whether optional host permissions could work without breaking its stated purpose. The manifest also requests `activeTab`, `tabs`, `storage`, `downloads`, `nativeMessaging`, `webRequest`, and `webNavigation`; retain only permissions needed by shipped features. Mozilla requires necessary permissions and prohibits executable remote code. The extension's current extension-page CSP is self-only; keep scripts packaged and reviewable.
3. **Make the reviewer path reproducible.** Provide the original readable source, build instructions, the exact test steps, and any accounts needed for review. Explain the separate Windows companion install and how reviewers can test a public, non-live sample. Avoid asking reviewers to use private accounts. Mozilla requires source for minified/transpiled/generated code and does not allow obfuscated code. See [submission guidance](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/) and [Add-on Policies](https://extensionworkshop.com/documentation/publish/add-on-policies/).
4. **Audit the companion installer and dependencies.** Keep the native host allowlist limited to Visave's stable extension ID, explain what Setup registers, and verify install, upgrade, and uninstall paths. The public Windows release ZIP excludes FFmpeg binaries. Setup downloads the pinned Gyan FFmpeg 9.0.2 archive directly from Gyan's publisher release and verifies both the archive and extracted executable hashes before installing it privately. This removes a Visave redistribution of that FFmpeg binary, so a Visave-hosted corresponding-source archive for it is not a release gate. Keep the publisher URL, version, hashes, and clear GPLv3 attribution/build-source link with Setup and release documentation; the Gyan build page identifies source revision `946fcce07b` and its build details. Users who separately redistribute the downloaded FFmpeg binary remain responsible for the applicable GPL source and notice requirements. Do not later add the binary to a Visave ZIP or mirror without first preparing the matching corresponding source and notices for the exact Gyan build and its statically linked dependencies. The generated Python runtime also carries licenses with its package metadata: the shipped yt-dlp wheel is Unlicense, while Mutagen is GPL-2.0-or-later; retain package source and all wheel license/notice files in any installer or source bundle. Check [Gyan's 9.0.2 build page](https://www.gyan.dev/ffmpeg/builds/), [the exact FFmpeg source revision](https://github.com/FFmpeg/FFmpeg/commit/946fcce07b), [FFmpeg's license notes](https://ffmpeg.org/legal.html), [yt-dlp licensing](https://github.com/yt-dlp/yt-dlp#licensing), and [Node.js licensing](https://github.com/nodejs/node/blob/main/LICENSE). A dependency license does not grant rights to videos users download.
5. **Publish a useful privacy policy and support contact.** Link this project's privacy notice from the listing and the public release page. Keep it aligned with the shipped code and the manifest. State plainly that Visave has no account, analytics, or Visave-operated upload service, if that remains true. Explain local inspection, native messaging, cookie opt-in, and that a download connects to the source platform.
6. **Use an honest feature description.** Do not promise that a list of extractors guarantees a successful download. Site changes, login restrictions, unavailable media, Firefox permissions, and player formats can prevent detection or downloads. Keep the existing DRM and live-stream limitations visible.

AMO submissions are subject to automated checks and can be manually reviewed. An unlisted signature is not an AMO policy exemption. For public AMO listing, prepare screenshots, description, support contact, privacy link, categories, reviewer instructions, and a versioned source archive. See [Mozilla's listing submission guide](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/).

## Platform terms and rights

These are separate questions from whether Mozilla signs the extension. YouTube's [Terms of Service](https://www.youtube.com/t/terms) limit downloading or otherwise using service content to cases expressly authorized by YouTube or covered by prior written permission, and prohibit automated access outside stated exceptions. Instagram's [Terms of Use](https://help.instagram.com/581066165581870) and [Meta's automated data collection terms](https://www.facebook.com/legal/automated_data_collection_terms) restrict automated collection without authorization. Visave's local helper uses yt-dlp to fetch media from the selected platform after a user starts a download, so users should assume that a platform may disallow that method unless the platform expressly permits it.

Tell users to use Visave only for material they own or have permission to save, where the platform's current terms permit the method. For YouTube, prefer YouTube's own download or creator export feature when available. Do not recommend downloading private, paywalled, removed, or otherwise access-restricted content; do not use another person's login; do not defeat access controls, DRM, or anti-copy restrictions; and do not redistribute or monetize copies without the needed rights. The extension rejects detected encrypted media, but that is a technical limit, not a legal clearance. Copyright permission, platform contract terms, and anti-circumvention law are distinct. The [U.S. Copyright Office's DMCA overview](https://www.copyright.gov/dmca/) describes separate restrictions on circumventing access controls; laws differ by location.

Avoid language such as “download anything,” “works on every site,” or “copyright-free.” The product must not imply that installation or personal use makes a download authorized.

## Current release blockers to check

- Confirm Firefox's install and upgrade consent prompts for the declared `browsingActivity`, `websiteContent`, and `websiteActivity` categories. The `none` declaration issue is corrected in 0.3.1; AMO reviewer validation is still needed.
- Confirm the native host's allowed extension ID and ensure the signed AMO package uses that exact ID.
- Review trademark/name use. The current extension display name is `senzdev | visave`; do not present Visave as affiliated with Mozilla, YouTube, Instagram, or Meta.
- Rebuild and inspect final extension and Windows packages. Check licenses, dependency notices, signatures/hashes, clean install, upgrade, uninstall, and Firefox restart behavior.
- Confirm the final Windows release ZIP contains no FFmpeg executables and Setup downloads only the pinned publisher archive, verifies both hashes, and displays the download/source attribution. If packaging changes to redistribute FFmpeg, block release until matching corresponding source and notices are ready.
- Provide AMO reviewers with honest test steps and a test URL that does not require private credentials.

The current source-package script uses an inclusion list and excludes `tools/generated`, so it does not package the root `test-results` directory or generated installers. Keep that whitelist approach. Before publishing a source archive, inspect its contents and omit screenshots, test outputs, logs, local profile paths, and downloaded media; include the public privacy and release documents.
